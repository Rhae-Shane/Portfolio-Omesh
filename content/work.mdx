#### Web and Turborepo

I migrated the whole frontend from a single Next.js repo into a Turbo monorepo. The old layout broke once we split apps — shared packages, env, native bindings, and deploy all assumed one Next output.

<ValiddTurboSplit />

<ValiddDeployPipeline />

Four apps now: marketing, blogs, deeplinks, and the investor dashboard, plus shared packages for common, db, ui, and the ESLint / TypeScript / Tailwind configs.

- Next only reads env from each app folder, not the repo root — the build script copies the root env into every app first
- The lockfile was made on Windows, so Linux runners missed optional natives — a CI script installs them
- Four parallel Next builds OOM'd the self-hosted runner — Turbo concurrency is 1 on deploy
- Local gateway on port 3000 matches production nginx so home, blog, dashboard, and universal links feel like one site
- Server routes I wired: /api proxy to the Express backend (no CORS), Groww/SIF handlers kept off that proxy, and Strapi revalidate for blogs
- ESLint 9 flat config across apps and shared packages; Vitest through Turbo; CI is lint → typecheck → test
